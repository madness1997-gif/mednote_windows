# M4.3 PDF–Note integration

M4.3 closes the native M4 loop without adding a browser editor or a second
SheetContent model. PDF crop output is embedded directly into the active
RichEdit RTF document, while source navigation remains shared metadata in the
Document graph.

## Crop handoff

Finishing a Reader crop now sends the PNG to the active Sheet. The editor
inserts a two-column image-and-notes block and a readable source caption, then
Reader-only mode opens the split workspace. The toolbar's column ratio and row
height selectors control the next crop block.

Before saving the crop, Reader flushes the current Document record into the
native graph. `SaveLinkedSheetContentAsync` then commits these values through a
single manifest replacement:

- the complete post-insertion RTF Sheet body;
- a `NoteDocumentLink` from the source Document to the active Sheet;
- a `content` relation containing PDF page and `x1/y1/x2/y2` coordinates.

The immutable RTF blob is written before the manifest is replaced. If RTF
insertion, graph validation, or persistence fails, the RichEdit document is
restored to its exact pre-insertion RTF and neither half becomes current.

## Return to source

The Note sidebar lists PDF sources for the active Sheet only. Selecting one
opens its persisted local path when necessary, switches Note-only mode to the
split workspace, navigates to the anchored page and scrolls toward the anchored
rectangle. A teal focus overlay marks the exact PDF region for 3.6 seconds; it
is presentation-only and never becomes an annotation.

Missing or identity-changed local files fail explicitly without changing the
current PDF. Source coordinates stay in the same unrotated PDF coordinate
system as M3 annotations, so zoom, fit mode, DPI and Reader rotation do not
rewrite the anchor.

## Native block controls

The RichEdit toolbar can insert blank 2×2, 3×2, and 3×3 RTF tables. First Aid,
generic tables and crop blocks use 12 pt Segoe UI and never insert a `Nội dung`
placeholder. New two-column blocks support 30/70, 50/50, or 70/30 column ratios;
new rows support 24, 36, or 52 pt minimum heights.

Windows App SDK RichEdit exposes text, paragraph, and character formatting but
no supported live table-resize object model. M4.3 therefore applies explicit
layout presets at insertion time and keeps the resulting table editable as
ordinary native RTF. It does not introduce a parallel HTML/canvas runtime merely
to provide drag handles.

## Boundary after M4

Reverse RTF→web conversion, Google Drive sync, installer/update work, crash
diagnostics and hardened shutdown coordination remain M5 concerns.
